# IE TS Implementation Plan

**Goal:** Expose repository-based TS form CRUD and automatic WEBFORM Form/Flow creation, with Thai integration documentation.

**Architecture:** Keep the three IEDOC entities in the requested webform entity folder. An IE-TS module provides validated nested DTOs, a controller, service orchestration, and a BaseRepository using webformConnection so Form/Flow and cross-schema TS writes share a transaction, following Jig.

**Tech Stack:** Existing NestJS, TypeORM, class-validator, Jest.

**Spec:** User request in this chat: CRUD under src/webform/ieform/IE-TS, repository pattern, insertion guide, auto_insert_ts_process creates Form/Flow before inserting with generated CYEAR2/NRUNNO.

## Constraints and decisions

- HEADERS contains one or more SEQ records; DETAILS references these SEQ records; FILES belongs to the form.
- Normal insert requires an existing WEBFORM.FORM. Automatic insert accepts REQBY, INPUTBY, optional REMARK/DRAFT instead of CYEAR2/NRUNNO.
- Update replaces the complete TS payload atomically; delete removes TS rows only. WEBFORM workflow lifecycle remains with existing APIs.
- Validate lengths, numeric precision, required keys, duplicate composite keys and detail/header references before writing.
- Lock existing FORM rows for mutations; automatic numbering uses the same Oracle FORM table lock as Jig.
- No changes to existing user edits in create-form.service.ts or PS-ADJ.
