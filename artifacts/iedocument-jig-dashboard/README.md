# Dashboard สำหรับ Jig API ใหม่

นำไปแทนเพียงสองไฟล์ใน iedocument:

- `assets/scripts/jig/dashboard.js`
- `application/views/jig/dashboard.blade.php`

ไฟล์บน shared server ยังไม่ได้ถูกเขียนทับ และไม่ได้แก้ backend เพิ่มในงานนี้

## สิ่งที่ปรับ

- ใช้ `SCHEDULES`, `CURRENT_FORM`, `DUE_STATUS`, `IS_NEW_JIG`, `CHECKPOINT_COUNT` จาก API ใหม่
- แสดงสถานะทะเบียนครบ รวมถึง DRAFT/PENDING/INACTIVE/DELETED/TRANSFERRED และสถานะรอบตรวจ
- แสดงคำเตือนครบกำหนดแยกจากสถานะกำลังตรวจ
- เพิ่มตัวเลือก FY (เมษายน–มีนาคม) และแก้ New JIG ให้ใช้ค่าจริง
- เพิ่มตัวกรองเกินกำหนด กำลังตรวจ และไม่มี Check Sheet
- ระบุว่าจำนวน JIG ที่ตรวจแล้วหมายถึงอนุมัติอย่างน้อยหนึ่งรอบใน FY ไม่ได้หมายความว่าครบทุกรอบทั้งปี
- แสดงวันที่ ISO ตามปฏิทิน Asia/Bangkok ป้องกันวันที่ 1 กลายเป็นเดือนก่อนหน้า
- เปิดรายละเอียดทะเบียน Check Sheet ประวัติฟอร์ม ผลตรวจ NG และรายชื่อไฟล์แนบในหน้าต่างอ่านอย่างเดียว
- ป้องกัน response ของ FY เก่าเขียนทับ FY ใหม่ และเพิ่มปุ่มลองใหม่เมื่อโหลดไม่สำเร็จ
- Export CSV ตามตัวกรอง พร้อมป้องกันข้อความที่อาจถูก Excel ประมวลผลเป็นสูตร
- Add JIG เป็น Modal บันทึกผ่าน POST `/iedoc/jig` โดยใช้ `$empno` จาก login เป็น `CREATE_BY` (Inputer) และรีเฟรช dashboard หลังบันทึกสำเร็จ

## Add JIG และผู้บันทึก

ผู้บันทึกอ่านจาก `$empno` ที่ iedocument ส่งให้ view อยู่แล้ว แสดงเป็นช่องอ่านอย่างเดียว และส่งค่าใน `JIG_CONFIG.empno` ไปเป็น `CREATE_BY` โดยไม่อ่านจากช่องแสดงผลดังกล่าว ผู้รับผิดชอบ `PIC_EMPNO` เป็นอีกฟิลด์หนึ่งและไม่ถูกตั้งให้เท่ากับผู้บันทึกอัตโนมัติ

Modal นี้สร้างทะเบียนสถานะ DRAFT เท่านั้น ยังไม่สร้าง WEBFORM หรือ flow อนุมัติ ในขั้นสร้าง WEBFORM ภายหลัง ผู้บันทึกจะใช้ชื่อฟิลด์ `INPUTBY` ของระบบ WEBFORM ซึ่งต่างจาก `CREATE_BY` ของทะเบียน Jig

เดือนกำหนดตรวจส่งเป็น `YYYY-MM-01` และ period/จำนวน/ราคาเป็น JSON number มีการกันกดบันทึกซ้ำ แสดงข้อผิดพลาดรหัสซ้ำ และเก็บค่าที่กรอกเมื่อบันทึกไม่สำเร็จ การระบุผู้บันทึกนี้ใช้ login context เดิมของหน้า ไม่ได้เพิ่มกลไกตรวจสอบตัวตนฝั่ง API ใหม่

## URL ที่ยังต้องเชื่อม

ไฟล์เดิมมีเพียง console.log สำหรับปุ่มต่าง ๆ ขณะนี้ Add JIG ทำงานเป็น Modal แล้ว แต่ยังไม่มีเส้นทางหน้าสร้างฟอร์มตรวจและหน้าอนุมัติให้ยืนยัน

ใน `JIG_CONFIG` ของ view:

- `inspectionUrl`: หน้าสร้างฟอร์มตรวจ รับ query `jigNo`, `SCHEDULE_DATE` (`YYYY-MM-01`), `FORM_TYPE=INSPECTION`, `empno`
- `formUrl`: หน้าแสดง/อนุมัติ WEBFORM เดิม รับ query `no`, `orgNo`, `y`, `y2`, `runNo`, `empno`

ค่าเริ่มต้นเป็นสตริงว่าง: ปุ่มเริ่มตรวจจะ disabled พร้อมคำอธิบาย ส่วนปุ่มดูรายละเอียด/ดูฟอร์มใช้งานได้ผ่าน API แบบอ่านอย่างเดียวแล้ว เมื่อมี URL จริงให้กำหนดค่าเหล่านี้และให้หน้าปลายทางอ่าน query ตามสัญญาข้างต้น หรือปรับชื่อ query ให้ตรงกับ controller เดิม

ที่อยู่ API คงค่าจากต้นฉบับไว้ใน `data-api-url="http://amecwebtest/api"` หาก environment เปลี่ยนให้แก้ที่จุดนี้ ค่า base URL และ empno อ่านจาก DOM เพื่อไม่แทรกค่า PHP ลงใน JavaScript string โดยตรง

หน้านี้ไม่สร้าง WEBFORM, ไม่กดอนุมัติ, ไม่เรียก finish อัตโนมัติ และไม่ส่งอีเมล การเลื่อนรอบยังเป็นหน้าที่ของกระบวนการหลังอนุมัติครบตาม backend

ไฟล์แนบแสดงชื่อ/ชนิด/ขนาดเท่านั้น เพราะ FILE_PATH ในฐานข้อมูลไม่ได้ยืนยันว่าเป็น URL ดาวน์โหลด

## การตรวจสอบ

ตรวจ JavaScript syntax และทดสอบ Chromium ด้วย jQuery จริงและ API จำลอง: การแสดงผล FY/6M, timezone, ตัวกรอง, pagination, search, รายละเอียด, escape HTML, export CSV, response สลับลำดับ และ error/retry ผ่าน

ยังไม่ได้รันบน PHP/Blade และ layout จริงของ iedocument หรือเชื่อม API จริง ภาพ dashboard-preview.png เป็นภาพจากข้อมูลจำลอง ไม่ใช่ข้อมูล production
